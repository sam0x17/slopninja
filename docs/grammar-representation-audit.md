The next representation change should add a compositional clause-child family alongside the existing fourteen families. The current clause-frame keys are sparse even across 300 training authors. Splitting each frame into its child relations gives similar clauses shared coordinates while retaining the original frame family for detailed comparisons. This is a change in comparison geometry over existing annotations; it does not add new syntactic evidence or establish an accuracy improvement.

The existing extractor already contains much of the requested information:

| Question | Existing representation | Remaining distinction |
| --- | --- | --- |
| Function words | All surface words and sentence-bounded word bigrams, plus POS, fine tag, and dependency distributions | Function-word identity attached to a grammatical role and parent POS |
| Auxiliaries and modality | AUX/POS-tag counts, morphology bundles, auxiliary dependency labels, and auxiliary slots in frames | Which auxiliary lemmas occur together at a particular clause head, with that clause's finite carrier |
| Negation | Surface-word counts and the parser's negation relation when present, including its location in frames and paths | Joint local patterns of operators and a negation-marked dependent; semantic scope remains unknown |
| Clause relations | Incoming relation in clause frames, including complements, adjunct clauses, relatives, and verbal conjuncts | Less sparse relation marginals, or lexicalized clause markers attached to their structural context |
| Shared structural fragments | Single dependency relations, POS windows, and bounded ancestor paths | Shared child-side slots across otherwise different full clause frames |

These distinctions follow directly from the implementation. [Word tokenization](../grammar/crates/grammar-core/src/features.rs#L77) preserves function words and internal apostrophes; it does not remove stop words. [Morphology](../grammar/crates/grammar-core/src/features.rs#L108) retains sorted bundles. [Dependency paths](../grammar/crates/grammar-core/src/features.rs#L129) retain dependency labels and ancestor POS with explicit ROOT/MORE endings, but no lexical identity or left/right direction. [Head frames](../grammar/crates/grammar-core/src/features.rs#L148) retain every lexical direct child, its side, relation, POS, order, and repeated occurrences. [Clause-head selection](../grammar/crates/grammar-core/src/features.rs#L167) is a syntactic proxy that also includes roots and fragments. [Clause frames](../grammar/crates/grammar-core/src/features.rs#L350) add the incoming relation and head morphology. The [syntax record](../grammar/crates/grammar-core/src/syntax.rs#L19) and [spaCy bridge](../grammar/crates/grammar-spacy/python/syntax_bridge.py#L64) already retain lemmas, although the default feature extractor never uses them.

The first extension has one new family, `clause_child_backoff_v1`. Its eligible heads and lexical children must match the existing clause-frame extractor exactly. For each such head, emit one event per lexical direct-child occurrence:

```text
incoming_relation|head_POS|side|child_relation:child_POS
```

Use `ROOT` for a self-headed root, `L` or `R` for the child's side in source order, and the parser's relation labels unchanged. A head with no lexical children emits exactly one `incoming_relation|head_POS|EMPTY` event. Preserve duplicate child occurrences. The distribution denominator is the total number of emitted child events plus EMPTY events, not the number of clause heads. This is the projection measured above. The audit JSON's phrase “preserves existing clause-head opportunities” refers only to the eligible head set; it must not be used as the new denominator.

For a synthetic annotation of “We might leave tomorrow,” the root verb can contribute separate subject, auxiliary, and adverbial slots. In “We might leave quietly tomorrow,” the shared slots still match, and the additional adverbial child increments the appropriate slot count. The full ordered frame changes. If two same-side children have different relation/POS pairs and exchange positions, their projected counts remain equal; the original full-frame family preserves that distinction. This deliberate loss of within-side order is how the new family shares evidence across larger frames. The original fourteen families remain available.

No head lemma, child lemma, morphology, or cross-child pair belongs in this first family. The retained incoming clause relation distinguishes, for example, a root verb's object from a complement verb's object. Head morphology remains in the existing morphology and full clause-frame families. A separate low-order context family would be another calibration choice; it is unnecessary to reproduce the measured projection and should wait for evidence.

Two later modules could add information that this projection cannot recover:

1. A function-word role distribution could emit one event per eligible parsed token: normalized function lemma, token POS, incoming dependency, parent POS, and side. A versioned eligibility rule should include ADP, AUX, CCONJ, DET, PART, PRON, SCONJ, and tokens explicitly marked with the parser's negation relation. Retain lemmas only for those tokens; omit content-word lemmas everywhere else. This is lexicalized grammar, so comparisons must not call it a purely grammatical ablation. For example, the same surface word used as an adposition or a clause marker would have different role keys. Its denominator would be the eligible token count.
2. A clause-operator signature could collect the ordered auxiliary/copular chain attached to each existing clause head, plus negation-marked dependents attached to that head or its collected operators. Traversal must stop before another clause or conjunct. Retain operator lemmas and tags; omit the lexical predicate's lemma. Record the finite carrier's observed morphology, with explicit NONE and MULTIPLE states when the parser supplies zero or several candidates. Modal identity and operator combinations would then be tied to a local clause rather than counted only as separate marginals. The denominator would be the eligible clause-head count, including explicit no-operator signatures. A dependency label must never be interpreted as a proof of logical negation scope, semantic modality, or factuality.

For every module, zero eligible opportunities means unavailable, following the current feature contract. An observed childless clause contributes EMPTY and is available; an empty document does not. Missing lemma or morphological fields require explicit missing-value treatment or a declared extraction error, rather than an inferred linguistic value. For the proposed operator family, no observed finite carrier is distinct from an asserted nonfinite clause. These details belong in the extractor identity and synthetic tests before any fitting.

Implementation should use a new `FeatureExtractor` wrapper around the unchanged `DefaultExtractor`, preserve all fourteen old family values, and declare a new feature-schema identity. A standalone CLI can derive the extension from a validated syntax document or from the exact versioned encoded clause-frame counts. The latter projection is mathematically sufficient for this first family and avoids reparsing, but it must reject other frame schemas and be checked against document-derived counts on the bound TRAIN caches. The old space, models, and portable Metric v1 artifacts remain bound to their original feature schema; a later experiment must fit and freeze a new space and family calibration explicitly.

That first extension is now implemented in [clause_composition.rs](../grammar/crates/grammar-eval/src/clause_composition.rs), with the separate [unslop-clause-composition CLI](../grammar/crates/grammar-eval/src/bin/unslop-clause-composition.rs). The identity is `grammar-features-v2;nfc-lowercase-letter-apostrophe-v1;alphabetic-parse-token-v1;syntax-families-v1;clause-child-backoff-v1`. It uses the exact original Unicode letter predicate, including the modifier-letter apostrophe that the separate word tokenizer handles differently. The implementation rejects reserved delimiters and unknown POS labels rather than accepting an ambiguous frame encoding.
